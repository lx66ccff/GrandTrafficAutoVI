# Contributing to GrandTrafficAutoVI

Thanks for your interest in contributing!

The project is currently in its planning stage. The most useful contributions are small, concrete, and reproducible.

## Before opening an issue

- Search existing issues to avoid duplicates.
- Describe the problem or proposal in plain language.
- Include a minimal example, expected behavior, and actual behavior where applicable.
- Keep suggestions within the project's simulation, visualization, tooling, or documentation scope.

## Pull requests

1. Keep each pull request focused on one change.
2. Explain the motivation and relevant design decisions.
3. Add or update tests when changing executable behavior.
4. Update documentation when interfaces or workflows change.
5. Do not include proprietary game assets, copied commercial content, credentials, or private data.

## Suggested labels

- `good first issue`: approachable starter tasks
- `simulation`: simulation models and scenario logic
- `gpu-compute`: GPU computation experiments
- `visualization`: rendering and visualization
- `documentation`: guides and project design
- `integration`: adapters and external-tool interoperability

## Design principles

- Prefer small, testable components.
- Keep core simulation logic independent from any one game engine.
- Make assumptions and units explicit.
- Favor deterministic tests where practical.
- Treat third-party tools as optional integrations, not mandatory dependencies.
